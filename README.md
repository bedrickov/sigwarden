## О проекте

При атаках программ-вымогателей (Ransomware) и скрытом саботаже инфраструктуры (Supply-Chain Tampering) ключевыми угрозами являются:
1. **Массовое шифрование файлов**: Вредоносное ПО обходит директории и заменяет структурированные данные (исходники, конфигурации, документы) на псевдослучайный шифротекст.
2. **Тихая модификация бинарников и скриптов**: Злоумышленник внедряет бэкдоры в существующие исполняемые файлы или служебные файлы деплоя без изменения размера файла.
3. **Отсутствие эталонного снимка (Baseline)**: Системные администраторы и DevSecOps инженеры часто не имеют легковесного инструмента для верификации сотен тысяч файлов на сервере за доли секунды.

**SigWarden** спроектирован для обеспечения непрерывной целостности файлов и раннего оповещения об угрозах:
- **Zero-C Dependencies (100% Pure Rust)**: Полная безопасность памяти без риска уязвимостей переполнения буфера (Memory Safety by default).
- **Потоковый хеш + энтропия в один проход**: Вычисление SHA-256 дайджеста и энтропии Шеннона (0.0 — 8.0 бит/байт) за один цикл чтения из дискового буфера без загрузки файлов целиком в оперативную память.
- **Детекция скачков энтропии (Entropy Spikes)**: Автоматическая классификация файлов. Если текстовый или бинарный файл с энтропией < 6.0 внезапно модифицируется в блок с энтропией > 7.4 бит, немедленно поднимается тревога `CRITICAL Ransomware Attack`.
- **Ловушки-приманки (Canary Decoy Tripwires)**: Размещение скрытых ловушек `.sigwarden_canary.tripwire`. При попытке шифровальщика изменить или удалить ловушку система мгновенно фиксирует компрометацию.
- **Криптографический манифест (Baseline Manifest)**: Генерация компактного JSON-слепка структуры файлов для регулярного аудита в пайплайнах CI/CD.

## Возможности

- **Субмиллисекундная проверка дельт**: Мгновенное сопоставление состояния директории с базовым манифестом: модификации, добавления, удаления файлов.
- **Пороговые условия для CI/CD (`--fail-on`)**: Возможность прерывать деплой или пайплайн сборки при обнаружении модификаций уровня `HIGH` или `CRITICAL`.
- **Автоматическое маскирование и игнорирование**: Исключение каталогов версионного контроля (`.git`), артефактов сборки (`target`, `build`, `node_modules`) для исключения шума.
- **Интерактивный ANSI CLI**: Удобная визуализация отчетов со сводкой целостности, временем сканирования и карточками инцидентов.
- **Машиночитаемый JSON-экспорт**: Нативный экспорт аудиторских отчетов для интеграции в корпоративные SIEM (Splunk, Elastic, Wazuh).

## Архитектура

```
sigwarden/
├── .github/workflows/
│   └── ci.yml                      # Автоматическая кроссплатформенная сборка и тестирование
├── src/
│   ├── lib.rs                      # Публичный интерфейс библиотеки ядра
│   ├── types.rs                    # Структуры данных (Severity, BaselineManifest, TamperFinding)
│   ├── entropy.rs                  # Расчет энтропии Шеннона и детекция всплесков шифрования
│   ├── hasher.rs                   # Потоковый 64KB буферизованный SHA-256 сканер
│   ├── canary.rs                   # Жизненный цикл анти-рансомваре ловушек (Tripwires)
│   ├── scanner.rs                  # Обход директорий, генерация манифеста и аудит дельт
│   ├── reporter.rs                 # Консольный ANSI рендерер и JSON сериализатор
│   └── main.rs                     # CLI точка входа
├── tests/
│   └── integration_tests.rs        # Комплексные тесты целостности, энтропии и ловушек
├── Cargo.toml                      # Манифест сборки Cargo
├── build.bat / build.ps1           # Автоматизация сборки под Windows
├── LICENSE                         # Лицензия Apache-2.0
└── README.md
```

## Сборка из исходников

### Требования
- [Rust](https://rustup.rs/) (версия 1.75 или новее)
- Windows, Linux или macOS

### Быстрый билд через PowerShell
```powershell
# Сборка Release бинарника и запуск всех тестов
.\build.ps1 -Test

# Очистка артефактов
.\build.ps1 -Clean
```

### Сборка через стандартный Cargo
```bash
cargo build --release
cargo test
```

Скомпилированный бинарник будет доступен по пути `bin/sigwarden.exe` (или `target/release/sigwarden`).

## Использование CLI

```bash
# 1. Создание криптографического эталона для текущей папки
sigwarden baseline . --out .sigwarden-baseline.json

# 2. Аудит директории относительно эталона
sigwarden verify . --baseline .sigwarden-baseline.json

# 3. Аудит с прерыванием пайплайна (exit code 1) при Critical/High нарушениях
sigwarden verify . --baseline .sigwarden-baseline.json --fail-on HIGH

# 4. Аудит с сохранением машиночитаемого отчета в JSON
sigwarden verify . --baseline .sigwarden-baseline.json --json audit_results.json

# 5. Установка скрытой ловушки-приманки от шифровальщиков
sigwarden canary deploy ./data

# 6. Проверка состояния ловушки
sigwarden canary check ./data

# 7. Анализ энтропии произвольного файла
sigwarden entropy --file suspicious_document.pdf

# 8. Каталог правил аудита
sigwarden rules
```

## Каталог правил

| ID | Важность | Категория | Описание |
| :--- | :--- | :--- | :--- |
| **SW-001** | `CRITICAL` | RansomwareAttack | Резкий скачок энтропии файла из структурированного диапазона ($<6.2$) в диапазон шифротекста ($\ge 7.35$) — признак работы шифровальщика |
| **SW-002** | `HIGH` | FileTampering | Несовпадение криптографической контрольной суммы SHA-256 с эталонным манифестом |
| **SW-003** | `CRITICAL` | CanaryTripwire | Ловушка-приманка `.sigwarden_canary.tripwire` была модифицирована, зашифрована или удалена |
| **SW-004** | `MEDIUM` | UnauthorizedFile | Обнаружен незарегистрированный / внедренный файл, появившийся после фиксации базового состояния |
| **SW-005** | `MEDIUM` | FileIntegrity | Контролируемый файл из эталонного манифеста отсутствует на диске |
